# Phase 12 — Forward evidence audit (pre-implementation)

State of the repository before the forward-monitoring build, and what Phase
12 attaches to. Written first, per the Phase 12 brief §1.

## Current forward/live model (Phase 9)

- `tools/forward-live.json` — hand-filled **aggregate** records only.
  Currently empty (`systems: {}`), which is the honest state: no forward or
  live record exists yet.
- `src/lib/forward-live.mjs` — `validRecord()` requires a named source, a
  stated period and at least one number; anything less is treated as absent.
- Rendering: `TrackRecordTabs` on every EA detail (block 03) with tabs
  Backtest / Forward / Live; the empty states read "No forward data
  available." / "No live data available."
- **Gap Phase 12 fills**: there is no *trade-level* ingestion, no importer,
  no metrics computation, no rolling windows, no degradation detection, and
  no distinction pipeline between FORWARD_DEMO and LIVE beyond the two keys.

## Evidence map / TYO SCORE connection

- `src/lib/evidence.mjs` — stages `backtest, oos, walkForward, monteCarlo,
  forward, live`; points 5/3/3/3/3/3. `forward: !!model.forward`,
  `live: !!model.live` (set in `build.mjs` from the Phase 9 validated
  records). All 14 systems currently 8/20 (backtest + Monte Carlo).
- `scoreV2()` — evidence carries 20 of 100 points; drawdown caps carry over.
- **Phase 12 change**: `model.forward` / `model.live` will be set from a
  *qualified* pipeline aggregate (min trades / min days / valid mapping /
  valid source, config-driven) or from a Phase 9 manual record that meets
  the same minimums. Unqualified data still renders (as monitoring), but
  does not light the stage.

## Terminal connection

- `src/pages/terminal.mjs` — evidence map (14×6), platform stats, research
  feed, lab hub. Reads `model.evidence` / `model.score` only.
- **Gap**: no forward status, no performance-monitoring table, no degradation
  summary. Phase 12 adds a monitoring section fed by the same aggregates.

## Research log connection

- `src/data/experiments.mjs` — experiments with AI provenance and the
  human-review safety gate (Phase 10).
- **Gap**: no "research candidate" concept. Phase 12 adds candidates as a
  separate, non-experiment artifact (`tools/research-candidates.json`),
  generated by degradation detection, never auto-promoted.

## Reusable parsers

- `tools/extract-trades.mjs` (library since Phase 8): `decode()` (UTF-16LE /
  Shift-JIS / UTF-8), `extractTrades()` for both tester dialects
  (MT5 13-col deals, MT4 9/10-col orders with side join). MT4/MT5 *account*
  statements use the same machine-generated table shapes, so the HTML source
  reuses this parser. Caveat: neither HTML dialect carries magic numbers →
  HTML imports need `--strategy` (MANUAL mapping) or comment fallback.
- `tools/lib-report-parse.mjs` — header/summary parsing (three dialects).
- CSV (MT5 "Deals" export or generic history export) is the preferred format
  because it can carry magic numbers and comments.

## Backtest data structure (comparison baseline)

- `tools/imported-reports.json` — per-slug header metrics (PF, DD + basis,
  trades, win rate, period).
- `tools/extracted-trades.json` — per-slug monthly/yearly series, counts,
  streaks, averages, period. Trades/month for the backtest baseline is
  derivable as `counts.closed / monthly.length`.
- `src/lib/ea-model.mjs` — merged frozen models; `model.num` numeric mirrors.

## Data that does not exist yet (owner-side)

- **No forward-demo trading history** for any of the 14 systems.
- **No live account history.**
- **No magic-number registry** (which magic each EA uses per account).
- Account metadata (broker, currency, account mode) for any future account.

Per brief §99: Phase 12 therefore ships the complete pipeline, tests it on
clearly-marked fixtures that never reach the production site, and leaves all
forward/live evidence honestly at NO DATA.

## Privacy baseline

The repository is **public**. Consequences for Phase 12 layout:

- `data/forward/raw/` and `data/forward/normalized/` are **gitignored** —
  raw statements and trade-level data never enter the public repo.
- Only aggregates (`tools/forward-aggregates.json`) and candidates
  (`tools/research-candidates.json`) are committed, restricted to the
  public-safe fields listed in `FORWARD_SECURITY_PRIVACY.md`.
- Account identity is internal-only: `ACC-FWD-001` / `ACC-LIVE-001`.
